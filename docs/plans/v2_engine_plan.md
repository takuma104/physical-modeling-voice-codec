# V2 計画（その 1）: CHIMERA エンジンの改良と「リアルさ」の要素の研究

## Context（背景と目的）

V1（エンジン無改造、日英 TTS、デモ、モデル、レポート）は完了し、公開済みです。本計画は
`docs/plans/idea_roadmap.md` の V2 の 1 項目め「CHIMERA エンジンの改良含む（鼻声対策等）、
よりリアルな音声生成に必要な要素の研究含む」を扱います。目標は、レポートが限界として挙げた
次の 2 つを両方上げることです。

- 話者の類似度（100 話者の中から本人が選ばれる割合は、話者ごとの当てはめをしても 14%。録音は 94%）
- NISQA の自然さ（品質のモデルでは合成音が上、自然さのモデルでは順位が逆）

V2 ではエンジンを改造できます。G2P なしの推論、参照音声からの話者、WebUI、V2 レポートは
別の計画にします。ただし「参照音声からの話者」の出力先になる**話者ベクトル**は、ここで設計します。

計画を立てるにあたって「何が足りないのか」を先に測りました（次節）。その結果、当初の想定
（エンジンの音色を直せば両方上がる）とは違う絵になったので、計画はそれに合わせてあります。

## 診断: 計画のために行った実験（2026-11-26）

共通の条件: JVS テスト（8 話者 × 25 文）、公開用エンコーダ J2 の合成音（`encv2`、`voices/v1.json`）、
話者照合は 100 話者を登録（各話者の学習用録音 20 文）、合成音は 24 kHz・録音と同じレベルに
揃えて比較。結果は `out/jvs/gap_encv2.json` と `out/jvs/v2_probe/`（スクリプト、ログ、試聴用クリップ）。

### 1. 話者性は「時間とともに動くスペクトル包絡」にある

新しい `pmvc.gap`（コミット済み）で、録音 R とその合成音 S を、フレームごとに
「スペクトル包絡」と「それ以外（倍音と雑音の比、パルスの位相、ゆらぎ）」に分け、互い違いに
組み直しました。合成音は録音と同じ時間軸・同じ高さなので、ボコーダなしでできます。

| | 本人率 % (WavLM / UniSpeech-SAT) | 本人との類似度 | NISQA 自然さ 女/男 | NISQA 品質 女/男 |
|---|---|---|---|---|
| 録音 R | 89.0 / 90.0 | 0.981 | 4.78 / 4.50 | 4.80 / 4.87 |
| 合成音 S（V1） | 5.0 / 2.5 | 0.918 | 4.14 / 3.57 | 4.03 / 4.04 |
| S に録音の包絡を載せる | **38.5 / 47.5** | 0.964 | 4.36 / 3.94 | 3.76 / 4.42 |
| 録音に S の包絡を載せる | 9.5 / 3.5 | 0.937 | 4.47 / 3.66 | 4.57 / 4.62 |
| S に、発話ごとに固定の補正カーブ（EQ） | **2.5 / 2.0** | 0.920 | 3.93 / 3.55 | 4.12 / 4.46 |
| S に、包絡の大まかな形だけ（傾きとレベル、毎フレーム） | 16.0 / 15.5 | 0.943 | 4.29 / 3.97 | 4.30 / 4.58 |

- 包絡さえ合えば、いまの声源のままで本人率は 5% から 38〜48% になる。逆に、本物の声源でも
  包絡が合成音のものだと誰の声か分からない（9.5% / 3.5%）。残り半分は声源側にある。
- 固定の EQ では 1 点も上がらない。照合モデルに見えている話者性は、音ごとに変わる包絡
  （その話者の声道がその音をどう響かせるか）にある。
- 帯域ごとに見ると、録音の 2.5〜5 kHz だけを合成音に置き換えたときが最も壊れる（25.5 / 29.0%）。
  ほかの 1 帯域でも 30〜62% まで落ち、合成音のどれか 1 帯域だけを録音に替えても戻らない（0〜11%）。
  どの帯域も合っている必要がある。

### 2. 包絡のずれの最大の成分は、全話者に共通の固定カーブ

母音の包絡のずれ（8 kHz 以下、形だけ）は約 10.5 dB rms で、内訳は次のとおりです。

| dB rms | 全体 | 性別に共通 | 話者ごと | 母音ごと | 話者×母音 | 残り（フレームごと） |
|---|---|---|---|---|---|---|
| 女性 | 10.7 | 6.8 | 4.1 | 2.9 | 1.6 | 6.4 |
| 男性 | 10.4 | 5.9 | 3.8 | 3.4 | 1.6 | 6.7 |

共通のカーブ（録音 − 合成音）: 女性は 3.3〜4.5 kHz が **11〜15 dB 不足**、5〜7 kHz が 5〜9 dB 過剰、
0.5〜1 kHz が 4〜6 dB 過剰。男性は 2.5〜3.5 kHz が **7〜12 dB 不足**、5.5〜6.25 kHz が 9〜14 dB 過剰。
女性の穴は、試聴で言われていた「華やかさ」の帯域そのものです。

既存のつまみを 1 つずつ動かすと、この穴を動かすのは `epilarynx`（喉頭の上の管の狭め）だけでした
（女性: 0 で +11.9 dB → 1.0 で +5.8 dB。男性: 0 で +14.3 → V1 の 0.78 で +10.1 → 1.0 で +7.2）。
最大にしても 6〜7 dB 残ります。エンジンの喉頭管は長さ 2.4 cm × 体格、上端の面積が 1.9〜0.35 cm² で、
V1 の高い声（`epilarynx` 0）では管として働いていません。梨状窩は 2 cm × 0.9 cm² の 1 本で固定です。
喉頭管と梨状窩（下咽頭）は、文献で 2.5 kHz 以上の話者差の源とされている部分です
（Kitamura ら 2005、Dang と Honda 1997 など。私の記憶によるので、着手時に確認します）。

### 3. NISQA の自然さの差は 0〜250 Hz にあり、およそ半分は「録音条件」

| NISQA 自然さ 女/男（104 文） | |
|---|---|
| 録音 R ／ 合成音 S | 4.78 / 4.51 ／ 4.13 / 3.55 |
| S の 0〜250 Hz だけを録音に替える | **4.76 / 4.39**（250〜500 Hz: 4.31 / 3.79、500 Hz〜1 kHz: 変化なし） |
| 同、無声の区間だけ ／ 有声の区間だけ | 4.59 / 4.12 ／ 4.20 / 3.72 |
| 録音から 0〜250 Hz を除く | 4.23 / 3.76（録音も合成音並みに落ちる） |
| S にハイパス（80 Hz） | 4.12 / 3.48（直らない。低域の過剰ではない） |
| S にノイズフロア（−45 dB）を足す | **4.51 / 3.97** |
| S に短い残響（0.15 秒、−18 dB）を足す | **4.36 / 4.10** |

- 自然さのモデルが見ているのは 1 kHz 以上ではなく、ほぼ 0〜250 Hz、それも主に無声の区間。
- 乾いた無雑音の合成音に、声と無関係なノイズフロアや残響を足すだけで、女性は +0.2〜0.4、
  男性は +0.4〜0.55 戻る。差（0.65 と 0.96）のおよそ半分は「無響・無雑音であること」への減点。
  無響室録音の TSP の実録音も 4.18 と低い（英語なので参考）。
- 残りは女性 0.3、男性 0.4〜0.5 ほど（録音条件の真似が粗いので幅がある）。これが声の分で、
  原因はまだ特定できていない。
- 別の予測モデル（torchaudio の SQUIM）では、合成音は録音より 0.2〜0.4 低いだけ。
- 既存のつまみ（ゆらぎ、開放率、閉じ方、非対称、すきま）で自然さが上がるのは +0.2 まで。
  男性は気息雑音を切ると −0.5。

### 4. 物差しの問題（今回見つけたもの）

- これまで合成音 48 kHz・録音 24 kHz で比べていた。女性の合成音は 24 kHz に揃えるだけで
  NISQA 品質が 3.85 → 4.35 に上がる（12 kHz 以上の成分が減点されていた）。レベルでも 0.2〜0.3
  動くようだ（こちらは対照を取っていない）。
- 照合モデルは固定の音色（EQ）に鈍感。音色の修正は、照合モデルでは測れない。
- NISQA の自然さは、ノイズと残響で上がる。これに合わせ込むと抜け道になる。

## 方針

1. **物差しを先に直す。**帯域とレベルを揃え、自然さは「乾いたまま」と「同じ録音条件を通したあと」の
   2 通りで出す。予測モデルを増やし、どれが耳に合うかを最初の試聴で決める。
2. **自然さ**は 2 つに分ける。録音条件の分は、出力段（マイクと部屋）として扱う。声の分
   （0〜250 Hz、無声の区間）は、原因を耳とトレースで特定してから直す。
3. **全員に共通の音色のずれ**は、エンジンを改造して直す（喉頭管と梨状窩が最優先）。これは
   2 つの指標には出にくい（照合モデルは固定の音色に鈍感で、自然さのモデルは 1 kHz 以上を
   見ていない）。それでも行う理由は、耳（女性の「華やかさ」）、NISQA の品質、そして 4 の前提に
   なること。どこまで進めるかは試聴で決める。
4. **話者性**は「動く包絡」なので、主役はエンジンの音色ではなく、**話者ごとの声道の形 ×
   話者を聞く学習**。V1 のリスナー（HuBERT 第 8 層）は話者を落とす表現なので、学習の中に
   話者の響きを求める項がない。まず、エンジンが「頼まれれば」録音の包絡にどこまで寄れるかを測る。

## 作業計画

各項目の進め方は V1 と同じです。測る → 仮説 → アブレーションかオラクルで確認 → 設定で
切り替えられる最小の変更 → 採点表 → 試聴ページに 2〜3 点 → 判定。耳で確かめるまで原因は断定しません。

### Phase 0: 物差し（小）

- `pmvc/bench.py`（新規）: 1 コマンドで V2 の採点表を出す。24 kHz・同じレベル・先頭の無音を
  除いて採点。再利用: `pmvc.whose.Verifier`、`pmvc.gap.identify`（100 話者登録）、
  `pmvc.natural.score`（乾いたまま／録音条件あり）、`pmvc.bands.measures`、`pmvc.nasals`、
  `pmvc.clicks`、`pmvc.judge`（Whisper、音声記号）。包絡のずれの分解（今回のスクリプト
  `out/jvs/v2_probe/scripts/env_decomp.py`）をモジュールにする。英語（TSP テスト）も同じ表に入れる。
- `pmvc/gap.py`: 帯域と区間（有声・無声・無音）の指定を足す（`low_probe.py` の内容）。
- 自然さの予測モデルを追加: SQUIM（`uv add torchaudio`）、UTMOSv2（サブモジュール、MIT）。
- V2 の試聴ページ（4 枚目、`pmvc/page.py`）。最初の中身は今回のハイブリッド。
  **耳合わせ①**: 「S に録音の包絡」は本人に近く聞こえるか。「録音に S の包絡」はどうか。
  ノイズフロアと残響で自然に聞こえるか。どの予測モデルが耳に合うか。
- V1 の基準値を新しい物差しで取り直し、下の目標値を確定する。

### Phase 1: 出力段と低域（小〜中）。Phase 3-1 と並行

- 出力段: マイクのハイパス、短い残響、ノイズフロア（既定は切）。`crates/pmvc-voice` に置き、
  Python と wasm の両方から使う。採点の「録音条件あり」はこれで行う。デモに入れるかは試聴後。
- 0〜250 Hz・無声の区間の差の特定: 録音にあって合成音にないものを区間ごとに比べ、
  `Voice.probe` で追う。候補は、有声から無声への声の止まり方、閉鎖中の声帯振動、無声区間の流れの
  低域。対策はエンジン側（Phase 2）か制御側。

### Phase 2: エンジンのフォークと、全員に共通のずれ（大）

- フォーク: `gh repo fork` で `takuma104/chimera-vocal-synth` を作り、サブモジュールをその
  `pmvc-v2` ブランチに向ける。上流の `AGENTS.md` の規約に従う（golden の re-bless、`bench`、
  サンプルレート耐性のテスト）。変更はすべて設定で切り替え、**既定では V1 と同じサンプルを出す**
  （回帰テストにする）。V1 のモデルとデモはそのまま動く。
- 2-1 喉頭管と梨状窩（最優先）: エンジンの周波数領域の計算（`airway/frequency.rs` の
  `transfer_function`）を `pmvc-engine` から呼べるようにし、2 節の共通カーブを目標に形を
  当てはめる。対象は `anatomy/human.rs` の `epilarynx_area` と `resample`（管の長さ、上端の面積、
  前庭）、`voice/human_airway.rs` の梨状窩（長さ、面積、左右 2 本）。時間領域で確認して試聴へ。
- 2-2 高域の損失: 粘性損失が周波数に依らない（`network.rs` の `viscous_omega`）。5〜7 kHz の過剰。
- 2-3 鼻と F1 帯（ロードマップの「鼻声対策」）: 女性の鼻音のレベル不足（4.6 dB）、0.6〜0.9 kHz の
  過剰。鼻腔の損失（`WALL_NASAL`、`viscous(2.5)`）、副鼻腔の数。`pmvc.nasals` で測る。
- 2-4 声源: 1.6 kHz 以上で倍音が雑音に埋もれる。閉じ方（`sources/glottis.rs` の `shape`）、
  気息雑音の帯域（いまは 300〜3500 Hz 固定）と声門の周期での変調、女性の 12 kHz 以上の成分。
- 2-5 子音（V1 の残り: 破裂の鋭さ、摩擦音の高域）。指標には出ないので優先度は低い。

### Phase 3: 話者ごとの「動く包絡」（大）。話者類似度の本丸

- 3-1 到達可能性の実験（Phase 0 の直後、V1 のエンジンで）: `pmvc.copysynth` の探索に包絡の距離を
  足し、テスト話者の 5 文ずつで、制御列と話者の設定を発話ごとに探す。エンジンは録音の包絡に
  どこまで寄れるか、そのとき本人率はいくつか（上限の目安は 38〜48%）。足りないのが
  「エンジンの形」か「エンコーダが求めていないこと」かを分け、Phase 2 と 3 の配分を決める。
- 3-2 話者ベクトル: V1 の 11 個（体格、声門、構え）に、Phase 2 で増える形（喉頭管、梨状窩、鼻）を
  足した 20 個前後の物理量。`pmvc/speaker.py` を拡張。録音条件（マイク）は入れない。
- 3-3 話者を聞く学習: リスナーを 2 つにする（何を言ったか = いまの HuBERT 第 8 層、どう響くか =
  包絡）。代役（`pmvc/standin.py`）に話者ベクトルを入力し、両方を予測させる（学習用のレンダは
  話者ベクトルを振って作る）。エンコーダ（`pmvc/encoder.py`）は話者ベクトルを受け取って制御列を書く。
  話者ベクトルも代役を通した勾配で当てはめ、実エンジンで確かめる。
- 3-4（必要なら）声源のチャネルを潜在表現に足す（開放率、傾き、気息をフレームごとに）。
  1 節の「大まかな形だけで 16%」が、いまのチャネルでは出せない場合。

### Phase 4: チェーンの作り直しと V2 エンジンの確定（中）

レンダ → 代役 → エンコーダ → TTS（日英）を作り直し、V1 と同じ採点表と試聴で比べる。
wasm の速度（実時間の 3 倍以上）を確認。デモへの反映は試聴後。手順は
`docs/experiments.md` / `experiments_ja.md` に追記し、V2 レポートの材料にする。

## リスク

- 自然さのスコアに合わせ込むとノイズで稼ぐ抜け道がある → 2 条件で採点し、最後は耳で決める。
- エンジンを変えるとエンコーダと TTS の作り直しが要る（1 回 1.5〜3 時間）→ ふだんは制御列を
  固定して比べ、作り直しは節目だけ。
- 包絡を追う学習が、話者ではなく録音条件を追う → 話者ベクトルは物理量に限る。
- Phase 2 の効果は 2 つの指標に出にくい → 物理的な計測と試聴で判定し、深追いしない。

## 承認時の既定（違う場合は指示してください）

1. 作業はローカルにできていた `v2` ブランチで進め、origin に push する（`pmvc/gap.py` は
   コミット済みで、push はまだしていません）。
2. エンジンの改造は GitHub のフォーク（`takuma104/chimera-vocal-synth`）に置く（Phase 2 の最初に作成）。
3. 判定用に torchaudio と UTMOSv2 を追加する。
4. V2 用の試聴ページを新設する（4 枚目）。
5. Phase 3〜4 の学習に galleria と galleria2 を使う（開始前に空きを確認。2026-11-26 に両方とも使用可と確認済み）。
6. 出力段（部屋とノイズフロア）は採点の条件として使い、デモに入れるかは試聴後に決める。
7. 承認後、本書を `docs/plans/v2_engine_plan.md` に置く。

## 検証

- 回帰: V1 の設定で V1 と同一サンプル（`pmvc-engine` のテスト、wasm は `tools/play_wasm.mjs`）。
  エンジン側は `cargo test --workspace` と `the_voice_holds`。
- 採点: `uv run python -m pmvc.bench out/jvs --variants <V1>,<変更後>` の表を、変更ごとに比べる。
- 診断の再現: `uv run python -m pmvc.gap out/jvs --variant <変更後> --enrol out/jvsall --out <dir>`。
- 試聴: V2 の試聴ページに各変更の 2〜3 点。デモは `node tools/test_browser.mjs`。
